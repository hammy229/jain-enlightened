# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities through public GitHub issues, pull requests, or discussions.

Report them privately using GitHub private vulnerability reporting:

1. Go to the **Security** tab of this repository.
2. Select **Report a vulnerability**.
3. Describe the problem, the affected area (web, admin panel, API, or mobile app), and steps to reproduce. Include the version or commit if you know it.

Reports sent this way are visible only to the maintainers. If you do not see the **Report a vulnerability** option, private reporting may not be enabled for this repository yet. In that case, open a public issue that says only "I have a security report and need a private channel." Do not include any details of the issue in that public issue.

## What to include

- A clear description of the issue and its impact
- Steps to reproduce, or a proof of concept that does not harm real users or data
- The affected component and file paths, if known

## What not to do

- Do not test against systems you do not own or have permission to test.
- Do not access, change, or delete real user data while testing.
- Do not publish details before the maintainers have had a reasonable chance to respond.

## Secrets

If you find a credential, API key, or private key in the repository or its history, report it through the same private channel. Do not paste the secret into an issue or a pull request.
